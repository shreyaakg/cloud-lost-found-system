## Cloud Computing Fundamentals

**Q1. What is cloud computing?**
Cloud computing means using computing resources (servers, storage, databases, networking) over the internet instead of owning physical hardware. You pay for what you use, like electricity.

**Q2. What are the three main cloud service models?**
- IaaS (Infrastructure as a Service) — you get a virtual machine, you manage the OS and software. Example: AWS EC2.
- PaaS (Platform as a Service) — provider manages the infrastructure, you only deploy your code. Example: Render, Heroku.
- SaaS (Software as a Service) — fully managed software accessed via browser. Example: Gmail, Google Docs.

**Q3. What is virtualization?**
Virtualization is the technology that allows one physical server to run multiple virtual machines simultaneously. Each VM behaves like a separate computer with its own OS. AWS EC2 uses virtualization to provide virtual machines to customers.

**Q4. What is the difference between IaaS and PaaS?**
With IaaS (EC2), you control the OS, install software, configure Nginx and Gunicorn yourself. With PaaS (Render), you just push your code and the platform handles everything else automatically.

**Q5. What are the advantages of cloud computing?**
- No upfront hardware cost
- Scale up or down as needed
- Pay only for what you use
- Accessible from anywhere
- High availability and reliability

## AWS EC2

**Q6. What is Amazon EC2?**
EC2 (Elastic Compute Cloud) is AWS's IaaS service. It provides virtual machines called instances that run on AWS physical servers. You choose the OS, instance type, and configure everything yourself.

**Q7. What instance type did you use and why?**
t2.micro — it has 1 vCPU and 1 GB RAM, is Free Tier eligible, and is sufficient for a college project Flask application.

**Q8. What is a Security Group?**
A Security Group is a virtual firewall for an EC2 instance. It controls which inbound and outbound traffic is allowed. We opened port 22 (SSH, admin only), port 80 (HTTP, public), and port 443 (HTTPS). Port 5000 was NOT opened because Flask's dev server should never be exposed publicly.

**Q9. What is a key pair and why is it needed?**
A key pair consists of a public key (stored by AWS) and a private key (.pem file, downloaded by you). SSH uses asymmetric encryption — you prove your identity using the private key without sending a password over the network.

**Q10. Why did you use Nginx and Gunicorn instead of running Flask directly?**
Flask's built-in server is single-threaded and not suitable for production. Gunicorn runs multiple worker processes to handle concurrent requests. Nginx sits in front as a reverse proxy — it serves static files directly (faster) and forwards dynamic requests to Gunicorn via a Unix socket.

**Q11. What is systemd and why did you use it?**
Systemd is the Linux service manager. We configured Gunicorn as a systemd service so it starts automatically when the EC2 instance boots and restarts automatically if it crashes.

## Amazon S3

**Q12. What is Amazon S3?**
S3 (Simple Storage Service) is AWS's object storage service. Files are stored as objects in buckets. It provides 99.999999999% (11 nines) durability and scales automatically.

**Q13. How did you organize objects in S3?**
We used a folder-like structure with object keys: `lost-items/<uuid>.jpg` for lost item images and `found-items/<uuid>.jpg` for found item images. UUID filenames prevent guessing and path traversal attacks.

**Q14. Why is the S3 bucket private?**
To prevent unauthorized public access to uploaded images. All four Block Public Access settings are enabled. Images are only accessible via presigned URLs generated by the application.

**Q15. What is a presigned URL?**
A presigned URL is a time-limited URL that grants temporary access to a private S3 object. It contains a cryptographic signature from AWS. Our URLs expire after 15 minutes. AWS credentials are never sent to the browser — only the signed URL.

**Q16. What is server-side encryption in S3?**
SSE-S3 (AES256) means AWS encrypts the object before writing it to disk and decrypts it when you read it. We apply `ServerSideEncryption='AES256'` on every `put_object` call in our code. This protects data at rest.

## IAM

**Q17. What is IAM?**
IAM (Identity and Access Management) is the AWS service for controlling who can access what. It manages users, roles, and policies.

**Q18. What is least privilege?**
Least privilege means giving a user or application only the minimum permissions it needs. Our IAM policy allows only s3:PutObject, s3:GetObject, and s3:DeleteObject on our specific bucket — nothing else.

**Q19. What is an IAM Role and why is it better than access keys on EC2?**
An IAM Role is attached to an EC2 instance. boto3 automatically uses temporary credentials from the role — no access keys stored in any file. Access keys are long-lived and can be leaked. Role credentials are temporary and automatically rotated by AWS.

## Flask and Application

**Q20. What is Flask?**
Flask is a lightweight Python web framework. It handles HTTP routing, templates (Jinja2), sessions, and request/response processing. We used Flask-SQLAlchemy for the database and Flask-Login for authentication.

**Q21. What is Gunicorn?**
Gunicorn (Green Unicorn) is a Python WSGI server. It runs multiple worker processes of the Flask application to handle concurrent HTTP requests. The start command is `gunicorn app:app` — module name `app`, application object `app`.

**Q22. How does Flask-Login protect routes?**
The `@login_required` decorator checks if the current user is authenticated. If not, it redirects to the login page. We also check `item.user_id == current_user.id` before allowing edit, delete, or recover operations.

**Q23. How are passwords stored?**
Passwords are hashed using PBKDF2-SHA256 via Werkzeug's `generate_password_hash()`. The hash is stored in the database. The original password is never stored. On login, `check_password_hash()` compares the entered password against the stored hash.

**Q24. What is SQLAlchemy?**
SQLAlchemy is a Python ORM (Object-Relational Mapper). It lets us define database tables as Python classes (models) and write queries in Python instead of raw SQL. Flask-SQLAlchemy integrates it with Flask.

## GitHub and Deployment

**Q25. What is in your .gitignore and why?**
We exclude: `.env` (contains secrets), `venv/` (virtual environment), `instance/` (SQLite database), `static/uploads/` (uploaded files), `__pycache__/`, and log files. These should never be committed to a public repository.

**Q26. What is Render?**
Render is a PaaS platform. We connect our GitHub repository, set the build command (`pip install -r requirements.txt`) and start command (`gunicorn app:app`), and Render automatically builds and deploys the application on every git push.

**Q27. Why does the database reset on Render?**
Render's free tier uses an ephemeral filesystem — it resets on every deploy. SQLite stores data in a file (`instance/lostfound.db`) which is lost when the container restarts. For production, a persistent PostgreSQL database would be used.

## Security

**Q28. What is HTTPS and why is it important?**
HTTPS (HTTP Secure) encrypts communication between the browser and server using TLS. It prevents man-in-the-middle attacks where someone intercepts the data in transit. boto3 uses HTTPS for all S3 communication by default.

**Q29. What is the difference between confidentiality and integrity?**
- Confidentiality: ensuring data is only accessible to authorized parties (private S3 bucket, presigned URLs, encrypted passwords).
- Integrity: ensuring data has not been altered (SHA-256 hash verification).

**Q30. How does SHA-256 verify file integrity?**
When a file is uploaded, we calculate its SHA-256 hash and store it in the database. When verification is requested, we retrieve the current file, recalculate the hash, and compare. If they match → INTEGRITY VERIFIED. If they differ → the file was modified.

## Matching Algorithm

**Q31. How does your matching algorithm work?**
We compare a lost item against all active found items using weighted token overlap across four fields: item name (35%), category (25%), location (25%), description (15%). Token overlap counts shared words divided by the maximum word count. If the total score is >= 50%, a match is created.

**Q32. Why did you choose token overlap instead of machine learning?**
Token overlap is simple, explainable, and requires no training data or external libraries. It is easy to demonstrate and explain in a viva. Machine learning would be over-engineering for a college project.

## Architecture and Scalability

**Q33. What is the difference between your PaaS and EC2 deployments?**
On Render (PaaS), the platform manages everything — we just push code. On EC2 (IaaS), we manually installed Ubuntu, Python, Nginx, Gunicorn, and configured systemd. EC2 gives more control but requires more setup.

**Q34. How would you make this application more scalable?**
- Replace SQLite with PostgreSQL (handles concurrent writes)
- Use AWS RDS for managed database
- Add AWS CloudFront CDN for faster image delivery
- Use AWS Auto Scaling to add EC2 instances under load
- Use AWS Elastic Load Balancer to distribute traffic

**Q35. What would you change for a real production deployment?**
- Add HTTPS with Let's Encrypt SSL certificate
- Use PostgreSQL instead of SQLite
- Add email notifications using AWS SES
- Implement rate limiting to prevent abuse
- Add CloudWatch monitoring and alerts
- Use IAM Role on EC2 instead of access keys
- Enable S3 versioning for object recovery
